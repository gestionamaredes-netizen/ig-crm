## 35 — El modelo BLUR Growth System

```
STRATEGY        → diagnóstico + investigación + posicionamiento (documentos 01-03)
     ↓
CONTENT         → pilares, series, hooks, guiones (documento 05)
     ↓
CREATORS        → Marco (verificado) + roster de Cuervo Produce (documento 06)
     ↓
DROP            → arquitectura de niveles, evento de lanzamiento (documentos 03, 06)
     ↓
TRAFFIC         → contenido orgánico + campañas pagas escaladas con datos (documento 08)
     ↓
CONVERSION      → landing, WhatsApp, sistema de ventas (documento 07)
     ↓
DATA            → CRM, tracking, dashboard (documento 07)
     ↓
OPTIMIZATION    → sistema de experimentación, KPIs (documento 08)
     ↓
NEXT DROP       → vuelve a CONTENT con datos reales en vez de hipótesis
     └──────────────────────────────────────────────────────────────┘
```

Lo que hace que esto sea un **sistema** y no una serie de campañas sueltas es el cierre del loop: cada vuelta a `CONTENT` parte de datos del `DATA`/`OPTIMIZATION` del ciclo anterior, no de la intuición inicial de este documento. Los documentos 01-06 son el estado inicial del sistema (avatares hipotéticos, competidores relevados por búsqueda, un creator sin verificar) — el objetivo explícito de los primeros 90 días (documento 08) es reemplazar cada hipótesis marcada en este proyecto por un dato propio de Tony.

## Por qué Tony Importados puede ser un caso de estudio de BLUR

Condiciones que ya están dadas, según lo relevado en este proyecto:

- **El negocio ya tenía un sistema comercial (Drops) antes de tener un sistema de contenido** — es un caso donde la estrategia de growth no inventa la mecánica de venta, la traduce a narrativa. Eso es un argumento de caso de estudio más fuerte que "armamos una campaña de Instagram desde cero".
- **La categoría "Drop Commerce" (documento 02)** es un ángulo de posicionamiento propio que, si funciona, es un activo de comunicación reutilizable para BLUR con otros clientes de retail/reventa — no solo para Tony.
- **El doble público (consumidor/emprendedor) resuelto en una sola marca** es una decisión de arquitectura poco común, documentada con su propia lógica de riesgo (evitar el patrón MLM, documento 02) — material de caso de estudio con sustancia, no solo de resultados de vanidad (views, seguidores).

**Condición para que el caso de estudio sea publicable, no solo interno:** los datos que lo sustenten tienen que ser reales (documento 08, KPIs), no las hipótesis de este documento inicial. Un caso de estudio armado sobre proyecciones en vez de resultados reales es exactamente el tipo de promesa que este proyecto se comprometió a no hacer (ver reglas de trabajo, documento 00).
